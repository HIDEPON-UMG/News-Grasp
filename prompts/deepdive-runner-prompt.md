本リポジトリ内の prompts/deepdive-research-system.md を Read で読み込み、その指示に厳密に従って、**いま（このプロセス内で）本日分の DeepDive レポートを 1 本生成してください**。これは「構築途中の説明」でも「将来の予定」でもなく、**今この実行で完遂すべき実タスク**です。本プロセスは毎朝の日次 digest が終わった直後に、同じ news-grasp-runner.ps1 が DeepDive 用の別セッションとして起動したものです。無人の自動実行なので、ユーザーに確認や質問を返さず（AskUserQuestion は使わない・使えない）、テーマ選定・リサーチ質問・採否はすべて自分で決めて最後まで進めてください。

文体は prompts/style-guide.md を正本として参照し、翻訳調・文末反復・冗長さを避ける。

具体的な手順: (1) JST で当日日付と issue（YYYYMMDD）を確定 → (2) `.venv\Scripts\python.exe tools\get_recent.py` で直近 7 日の記事を取得し、**`build/deepdive-context/{YYYY-MM-DD}.json` を Read して過去DeepDiveとの構造化された接続候補だけを見る**。pack が無い場合は一度だけ `.venv\Scripts\python.exe -m tools.deepdive_context_pack --date {YYYY-MM-DD} --repo-root . --output build/deepdive-context/{YYYY-MM-DD}.json` で生成し、`digest/DeepDive/*.md` の過去本文を広範囲に Read しない。新規テーマは過去文脈なしで採ってよい。続報・主役共有・波及・対比として扱う場合だけ、context pack の候補から `related` ブロック（relation 種類〔続報/主役共有/波及/対比〕＋link 根拠＋change。date から URL・カテゴリ色を自動生成）を作る。件数合わせや「AI」だけの一致で無理に関連付けない。そのうえで、`data/articles.jsonl` の該当エントリの entities/topics を頻度集計して、速報性×奥行き×波及性で深掘りテーマを 1 つだけ選定 → 単一のリサーチ質問に言語化。**ここで深掘りに値する新規テーマが立たなければ、リサーチに進まず即休載**（テーマゲート＝コスト制御の核。無理に毎日出さない）→ (3) **fan-out は使わない**（並列 external fan-out 禁止・前回 415 万トークン失敗の真因）。この単一セッションで直列に WebSearch（英語＋日本語）→ WebFetch で一次ソースに到達する。**WebFetch は合計 6 件以内・1 ラウンド hard cap**（6 件で打ち止め、重複 fetch 禁止）。対向検証は別エージェントを立てずインラインで行い、裏が取れない数値・伝聞は「未確認」と明記するか落とす（推測で数字を埋めない）→ (4) `mkdir -p digest/DeepDive` のうえ `digest/DeepDive/{当日のJST日付}-DeepDive.md` を、スカラー frontmatter ＋ 3 節（## 背景 / ## 深掘り / ## 注目点 ＋ ## 要約 / ## 参考リンク）＋ 所定の fenced block（背景に timeline・players・**relations（関係図・必須）**、深掘りに **chart 最低 1（うち 1 つは時系列の数値変遷）と table（データ表・必須）**を source 必須で、注目点に decision を issue/options/deadline/decider の 4 キー必須）付きで生成 → (5) `data/_status.md` に生成または休載の結果を 1 行追記して停止する。**git add / git commit / git push は絶対に実行しない**。runner が DeepDive / data/_status.md の commit と publish を一元管理する。

必要なフォルダは mkdir -p で作成し、テーマが立った日はためらわずに 1 本生成してください。**既出テーマしか無い日・直近が薄く深掘り価値のある新規テーマが 1 つも立たない日は、digest を作らず data/_status.md に休載行を 1 行追記して終了**してください（日次化では休載はコスト制御として想定された正常動作です）。予算（--max-budget-usd）や時間に達した場合は、md を 3 節そろえて生成済みならそこで停止し、未完成なら休載扱いにしてください。commit / push / docs 生成 / publish gate は runner の責務です。

**`data/_session_urls.json` は触らないでください**（2026-06-05 案②-Lite 案③ hook 化）。本リポは `\.codex/settings.json` + `\.codex/hooks/append_session_urls.py` で PostToolUse:WebSearch/WebFetch を hook 化済みで、`WebFetch` を呼ぶたびにハーネス層が自動でこのファイルに観測 URL を append します。DeepDive 側はこのファイルを読み書きする必要はありません。push 前 gate (`tools/audit_all_article_urls.py --gate --match-session`) が hook が書いた白リストと `articles.jsonl` の当日 URL を物理照合します。
