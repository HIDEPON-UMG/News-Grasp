高機密クラウド、主権は運用設計へ

日本の高機密ソブリンクラウド構想は、AI時代の機密データ基盤をどの主体が実効支配するか

#deepdive#daily#news-grasp#issue-20260817#ソブリンクラウド#JWCC#日本政府#防衛クラウド#データ主権
BACKGROUND

背景

01 / 03

日本政府の高機密ソブリンクラウド構想は、単なるクラウド調達の話ではない。2026年7月の日本成長戦略は、機密性の高い情報について情報保全・秘密保全措置を備え、自律的な運営・管理を確保したクラウド活用を検討するとした。論点は「国内に置くか」ではなく「誰が鍵、権限、ログ、運用を支配するか」へ移っている。

米国防総省はJWCCで、AWS、Google、Microsoft、Oracleを選び、商用クラウド能力を全機密区分と戦術エッジまで調達できる枠を作った。これは単一ベンダー回避の仕組みだが、マルチベンダーであれば主権リスクが自動的に消えるわけではない。案件ごとの権限、監査、鍵管理が実装で決まる。

英国防省も、Digital Backbone の一部として hyperscale cloud を全分類に広げる方針を示した。ここで重要なのは、クラウドを「外部委託」と見るのではなく、AI、データ分析、作戦上の意思決定速度を支える基盤として位置づけている点だ。閉域網だけで守る発想から、統制されたクラウドで処理する発想へ変わりつつある。

DEEP DIVE

深掘り

02 / 03

Gartnerの見通しでは、2026年のソブリン・クラウドIaaS支出は中国が470億ドル、北米が160億ドルとされる。地域別成長率では中東・アフリカ、成熟アジア太平洋、欧州が高い。政府と重要インフラが、通常クラウドとは別の統制を買い始めている。

ただし、日本政府の課題は市場規模に乗ることではない。高機密情報は、データ所在地だけでなく暗号鍵、ID、特権管理、監査ログ、運用要員、法的管轄まで一体で見なければならない。「国産か外資か」の二分法では、実効支配の設計を見落とす。

EXHIBIT D — データ表 / TABLE

DoDの生成AI Task Force Lima は、生成AIを安全に使うための評価・同期・導入を担う組織として置かれた。DefenseScoopの報道では、ソフトウェア開発、戦闘被害評価、公開情報と機密データを含む文書要約など、180超の利用可能性が語られた。AI活用の本丸は、機密データを安全に処理できる基盤の有無にある。

◇ 論点 — THE ISSUE

日本政府は高機密ソブリンクラウドを、国産化の看板ではなく実効支配の運用仕様としてどう設計するか

01

国内データセンター中心で所在地を優先する

02

米英型の複数クラウド調達を参照し、案件ごとに供給者を競わせる

03

所在地・鍵・ID・監査・AI利用・移行性を一体の統制仕様として定義する

期限 — DEADLINE

2026年中（日本成長戦略が一定の結論を求める期限）

決定権者 — DECIDER
  • 内閣官房
  • 関係府省
  • 防衛・重要インフラの情報システム責任者
  • クラウド調達・監査担当

国内データセンター中心の案は説明しやすいが、鍵、更新権限、運用者、監査ログが国外主体や単一事業者に偏れば、主権の実体は弱い。米英型の複数クラウド調達は競争を作るが、案件ごとの統制仕様が粗ければロックインは残る。第三案の一体仕様が最も重いが、機密AI時代の前提に近い。

私の読み筋は、高機密ソブリンクラウドを「製品名」ではなく運用仕様の束として扱うことだ。調達仕様には、暗号鍵の支配、特権操作の分離、ログの保全、AI推論へのデータ渡し、障害時の移行手順を並べて入れるべきだ。主権はスローガンではなく、日々の操作権限に宿る。

❖ 要約 — IN ONE READ

日本政府の高機密ソブリンクラウド構想は、クラウドを使うか使わないかではなく、AI時代の機密データ基盤を誰が実効支配するかを問う。米国JWCCと英国防クラウドは、商用技術を機密区分へ広げる先行事例である。日本は所在地、鍵、ID、監査、AI利用、移行性を一体の統制仕様として設計する必要がある。
