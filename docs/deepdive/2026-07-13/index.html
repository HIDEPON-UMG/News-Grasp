AI価格競争、単価から配布設計へ

BACKGROUND

背景

01 / 03

前回は値下げ検討と上場前の採算圧力を扱った。今回の変化点は、OpenAIがGPT-5.6をSol、Terra、Lunaの3階層で一般提供し、AnthropicもClaude Sonnet 5に8月末までの導入価格を置いたことだ。 競争は「一番安いモデルは何か」だけでなく、どの処理をどの階層へ流すかという配布設計へ移った。

供給側の二社は競合するが、企業ユーザーから見ればモデル名よりも処理の振り分け方が重要になる。 定型処理は低価格層、失敗コストの高い判断は上位層、繰り返し文脈はキャッシュへ流せば、単一モデルの値下げを待たずに費用を動かせる。価格表は調達の結論ではなく、ルーティング設計の入力値になった。

規制当局が見る市場もモデル単体では閉じない。 公取委の実態調査は、基盤モデルからクラウド、アプリケーションまで連なる競争を対象にしている。 安価な入口が将来の囲い込みにつながるか、乗り換え可能性を保てるかが価格競争の裏側に残る。

DEEP DIVE

深掘り

02 / 03

時系列が示すのは単純な全面値下げではない。 低価格の汎用選択肢はGPT-4oの入力2.5ドル・出力10ドルから、GPT-5.6 Lunaの1ドル・6ドルへ下がった一方、Solは5ドル・30ドルのプレミアムを置いた。 安価な入口を広げながら、高難度処理には上位単価を取る階層化が進んでいる。

同じ単価表でも実際の請求額は処理設計で変わる。 GPT-5.6はキャッシュ読み取りを通常入力の10%とし、Claude Sonnet 5もキャッシュ読み取りを入力0.20ドル、9月以降0.30ドルに設定している。 Anthropicは新しいトークナイザーにより同じ文章でも約30%多くトークン化され得ると説明しており、比較すべきは1トークンの値段ではなく、同じ仕事を終える総トークン数、再試行、待ち時間を含む完了単価だ。

EXHIBIT D — データ表 / TABLE

企業側の交渉力はモデルを混ぜられるほど高まる。 LunaとSonnet 5導入価格の差は入力1ドル、出力4ドルだが、品質要件の違う全処理を一括移行すれば失敗時の手戻りが増える可能性がある。 低価格層を大量処理へ、高価格層を例外処理へ割り当て、実測した完了単価で配分を更新する企業ほど価格競争の果実を取り込みやすい。

◇ 論点 — THE ISSUE

企業はAIモデルを単一社へ集約するか、処理別ルーティングで価格階層を使い分けるか

01

上位モデルへ集約して品質と運用を単純化する

02

低価格モデルへ寄せて利用量を優先する

03

複数モデルを処理別に振り分けて完了単価を最適化する

期限 — DEADLINE

2026-08-31 Claude Sonnet 5導入価格の終了前

決定権者 — DECIDER
  • 企業のAI基盤責任者
  • CFO・調達部門
  • 業務部門のプロダクト責任者

集約は監査と運用を簡素にするが、価格改定や障害の影響を一社へ集中させる。低価格への全面移行は利用量を増やせる半面、失敗時の再試行や人手確認が費用を戻しかねない。複数モデルのルーティングは設計と評価の負荷が増えるものの、価格階層を実需へ結び付けられる。 含意は、8月末までに最安モデルを決めることではなく、同じ業務を複数モデルで測り、9月の価格改定後も切り替えられる評価基盤を持つことだ。

❖ 要約 — IN ONE READ

GPT-5.6の三層価格とClaude Sonnet 5の期限付き導入価格により、AI価格競争は一律値下げから処理別の階層設計へ移った。 入出力単価だけでは総費用を測れず、キャッシュ、生成量、再試行を含む完了単価が判断軸になる。企業は8月末までに複数モデルを同一業務で測り、切り替え可能なルーティングを整える必要がある。
