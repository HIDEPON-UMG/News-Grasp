記事鮮度・品質検証ゲート

偽日付事故 (実発表 2026-03-05 の記事を date: 2026-06-11 で TOP 掲載) の恒久対策。LLM 自己申告 date を独立証拠 (htmldate / Wayback CDX) とクロスチェックし、乖離記事を push 前に公開不能にする。

実装済み・実測検証済み News-Grasp

概要

2026-06-11 号で、LLM 生成セッションが自己申告した偽日付により 3 ヶ月前の記事 (OpenAI GPT-5.4) が当日記事として digest TOP・LP ヒーローに掲載された。既存の鮮度ゲート 2 箇所 (dedup の freshness-gate / validate_daily_quality の _stale_*) は正常動作していたが、日付の独立証拠が「URL パス内の日付」1 系統しかなく、URL に日付が無い記事は LLM の自己申告 date を無条件に信頼する fail-open 構造だった。

実測で確定した構造的死角

candidates 段階に date フィールドが無く、append 時に当日日付を強制付与。extract_source_date_from_url が None を返す記事 (例: openai.com/index/introducing-gpt-5-4/) は鮮度検証を素通り。さらに E2E 実測で「正常」と思われていた 06-10 号も 29 件中 14 件が古記事 (最古 854 日前) と判明し、品質低下は構造的に進行していた。

確定ポリシー (2026-06-11 ユーザー決定)

htmldate None 時は Wayback CDX 併用 fail-close (古スナップ=fatal / スナップ無し=通過+警告 / CDX 失敗=ambiguous warn)。乖離許容 1 日 (タイムゾーン差のみ)。既存 URL パス日付チェック 2 箇所は早期 fail-fast として現状維持。出典整合 (タイトル突合) は警告モードで同梱。

判定値は max(初出日, 更新日) を上界に使う

初出日のみで判定すると live ブログ・リリースノート等の継続更新ページが誤爆する (実測: Google release-notes は初出 04-22 / 更新 06-09)。本当に古い記事は両方とも古い (GPT-5.4 検体は両方 2026-03-05) ため、上界判定で正当検知を保ったまま誤爆だけが消える。トレードオフ: dateModified を自動更新するフレッシュニング系サイトの偽装は逃す (Wayback / URL パス日付チェックが部分カバー)。

採用しなかった案

取込時 dedup に配置

却下

dedup は LLM セッション内呼び出しのため、呼び忘れ・失敗時に素通りし得る。さらに candidates 段階では date が未確定で突合対象が無い。

push 前境界 (step 2.6) に集約

採用

runner が決定論的に実行する唯一の HTTP 境界 (LLM バイパス不能)。並列 fetch・UA 3 段・ambiguous 処理を再利用でき、追加 HTTP は当日+前日分の full GET のみ。

日付の独立ソース比較

ソース採否根拠とトレードオフ
htmldate主系統公式評価 F1 0.949 / Recall 0.993。検体実測でメタ無しページの本文日付も抽出。日本語ページの本文テキスト抽出は弱い (メタ有なら可)。
Wayback CDXフォールバックclaimed より古いスナップ = 改竄不能な否定証拠。レート不安定 (実測 timeout 1 回) のため htmldate None の少数記事のみ。
URL パス日付既存 2 箇所維持早期 fail-fast。/YYYY/MM/DD/ のみ対応で月までの URL は素通り (新ゲートがカバー)。
RSS / sitemap不採用ソース毎の対応コストが高く htmldate + Wayback で同等以上。
HTTP Last-Modified不採用CDN / 動的生成で配信時刻が返る最弱シグナル。
first-seen 台帳不採用 (今回)初観測が当日なら通るため今回事故型を防げない。再出現検知用としてフェーズ 2 候補。

データフロー

runner step 2.6 (audit_all_article_urls --gate) 内の日付証拠検証。当日+前日 date のレコードのみ full GET し、同一 HTML を日付抽出とタイトル整合の両方に再利用する。

Wayback の判定

スナップショット無し = 新着の可能性が高いので通過 + 警告。CDX 失敗 (timeout) = ambiguous として警告のみ (オフライン誤発火防止、audit の既存設計と同型)。

実装ステップ

1. 検体実証htmldate が GPT-5.4 実 HTML から 2026-03-05 を抽出することを実測 (実装続行の前提)
2. 純関数化tools/date_evidence.py に fetch と判定を分離 (契約テストはオフラインで判定のみ叩く)
3. 境界統合audit_all_article_urls --verify-dates (--gate でデフォルト ON、脱出ハッチ --no-verify-dates)
