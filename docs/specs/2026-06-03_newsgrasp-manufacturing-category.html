Context — なぜ Mobility では足りないのか

News-Grasp は現在 6 カテゴリ (FX / AI / IT-Consulting / Mobility / Economy / Game) + Summary で日次メルマガと Obsidian digest を生成している。ところが既存の「Mobility」は Waymo / Tesla / BYD などのユーザー向けサービス寄りニュースに偏り、ユーザーが本当に知りたい「自動車 OEM の社内事例・車開発の新規/中止、Tier1 サプライヤーの技術開発・特許・R&D 戦略シフト、生産技術（ギガキャスト・全固体電池量産）」が拾われていなかった。

根本原因 — watchlist でなく「指標」の問題

Mobility の watchlist には既にデンソー・ボッシュ等の Tier1 が入っている。それでも製造ニュースが拾われないのは、現行の重要度スコア（routine-system.md 3-A.1）が「影響範囲 35%＝読者の行動が変わる人数」＋「話題性 30%＝拡散量」で計 65% を占め、消費者/投資家目線に最適化されているため。製造・技術・サプライチェーンの「地味だが構造を変える」ニュースは定義上この指標で負ける。よって watchlist 拡充では解決せず、指標そのものを変える必要がある（これがユーザーの「異なる指標が必要」という直感の正体）。

指標の差し替え — 3-A.1 ↔ 3-A.1-M

本カテゴリの本質はここにある。他カテゴリ（FX/AI/IT/Mobility/Economy/Game）は標準スコア 3-A.1 のまま。Manufacturing だけ専用軸 3-A.1-M で採点し、話題性（拡散量）を軸から外す。

3-A.1（標準・消費者/投資家目線）

軸重み
影響範囲（読者の行動が変わる人数）35%
話題性（拡散量）30%
その他（新規性・確度 等）35%

拡散量で測ると、特許分析や地域工場の動向は永遠に埋もれる。

3-A.1-M（製造専用・産業観測者目線）NEW

軸重み
産業インパクト30%
技術的新規性・深度25%
戦略的シグナル25%
一次情報度（IR/特許/取材）20%

話題性=削除 / 時間減衰=なし / 件数下限=3 件で可

3-A.1 との 3 つの差分

差分内容理由
話題性を軸から外す拡散量は重要度に直接寄与させない（ガードレール③の相対補正で間接的にのみ効かせる）「デンソー/アイシン特許分析」型は拡散しなくても構造的に重要
時間減衰を弱める3-A.1 ガードレール②「報道から24h超は話題性−10」を適用しない特許分析・戦略シフトはストック型で数日遅れても価値が落ちない
件数下限を緩める1 日の目標件数を無理に埋めず、該当が薄い日は 3 件で可質の低い続報で埋めない（3-A.5-F を特に徹底）

Runner パイプラインと製造で触る経路

パイプライン全体は Mobility 追加時と同じ。製造で増える/触る経路は スチールグレーで強調。特徴は (1) スコア採点が製造だけ 3-A.1-M に分岐する点、(2) Web 経路は CATEGORIES dict 駆動でほぼ自動対応・メール経路は routine 手組みで .acMf とデザイン表が要る点。

触る経路まとめ

  • Layer 1 (CLI): 変更なし。曜日判定で平日のみ製造を対象に。
  • Layer 2 (Search/Score/Dedup): watchlist.md に ## Manufacturing 追加 + routine-system.md に 3-A.1-M スコア特則と曜日マトリクス追記。dedup.py はカテゴリ非依存で変更不要。
  • Layer 3 (Artifact): config.py CATEGORIES に 1 行 → generate_pages.py は iterate 自動拡張。TAG_TO_CID に 製造→manufacturing、γ schema 8→9 で fallback 定数を リスト長連動化（今後の増減に自動追従）。
  • Layer 4 (Delivery): メールは routine 手組みなので .acMf クラスとデザイン表が必須。サムネは別 repo news-grasp-assets に画像 push。
技術メモ（踏むと事故る点）

① sections は dict[int]（1始まり）。製造を §06 に挿入したのでテストの期待 index がずれる。② fallback 定数の Mobility 抜けは積み残しバグだった（digest 正常時は動的パースが使われ顕在化していなかった）→ 今回是正。③ _fallback_sections は range(len(...)) と last = len-1 でカテゴリ増減に自動追従させ、ハードコード番号を残さない。
