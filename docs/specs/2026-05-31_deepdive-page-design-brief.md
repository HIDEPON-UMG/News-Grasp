## ここからが依頼文（コピペ範囲）

News-Grasp（個人ニュース要約サービス）の **「TODAY'S THEME」= 1 テーマ深掘りレポート（DeepDive）ページ**のビジュアルデザインを作ってください。日次の収集ニュース（digest）とは別に、直近のニュースから 1 つだけテーマを選び、一次ソースまで遡って「背景・深掘り・注目点」の 3 節で文脈化した読み物です。**毎回 1 ページ 1 テーマ**で、ページ冒頭に `━━ TODAY'S THEME` のラベルで主題を大きく提示します。

### 0. このページが描画する構造化ブロック（生成側が必ず出力するデータ）

レポートは Markdown ＋ fenced JSON ブロックで生成され、レンダラがこれを図表に変換します。デザインは以下の各ブロックの「見せ方」を設計対象とします（★は今回新規追加でレンダラ未対応＝描画方式の設計が必要）:

| 節 | ブロック | 中身 | 望ましい描画 |
|---|---|---|---|
| 冒頭 | frontmatter | title / theme / date / issue / tags / og_image | `━━ TODAY'S THEME` ラベル＋大見出し＋メタ（日付・issue・タグ） |
| 背景 | `timeline` | 時系列イベント（date/title/source/url/thumb） | 縦 or 横タイムライン（出典リンク・サムネ対応） |
| 背景 | `players` | 当事者の立場（name/role/move/position） | プレイヤーカード列 |
| 背景 | ★`relations` | 当事者「同士」の関係（nodes＋edges、edge に label と kind=競合/規制/提携/出資/対立/供給） | **関係図（ノード＋ラベル付き有向エッジの SVG ネットワーク図）** |
| 深掘り | `chart` | 数値（type=line/bar/stacked_bar、**最低 1 つは時系列の数値変遷**、source 必須） | 折れ線/棒グラフ（出典脚注固定） |
| 深掘り | ★`table` | 統計数値の比較・変遷（columns/rows、未確認欄は「未確認」表記、source 必須） | **整形済みデータ表（未確認セルは淡色/注記）** |
| 注目点 | `decision` | 意思決定フレーム（issue/options/deadline/decider） | 意思決定カード（選択肢・期限・決定権者） |
| 末尾 | 要約 / 参考リンク | リード文＋一次ソース一覧 | リード（OGP 流用）＋出典リスト |

本文は 3 階層強調（`[[固有名詞]]`＝最強マーカー／`**太字**`＝中／`__下線__`＝含意）を使うので、3 段階の視覚的ウェイトを用意してください。

### 1. トンマナ・デザイントークン

- **基調**: Claude.ai 公式トンマナ準拠（warm・落ち着いた知的さ）。プロジェクトに `DESIGN.md` があればそのトークンを一次ソースに、無ければ `~/.claude/templates/DESIGN.md` を展開して使う（`/design-md` skill）。
- **DeepDive アクセント色**: `#1A1A1A`（near-black。純黒 #000 は不可）。ラベルグリフは `❖`、ラベル語は `TODAY'S THEME`（既存仕様の `DeepDive` ラベルを TODAY'S THEME に読み替え）。
- **タイポ**: 本文＝Noto Serif JP（明朝）／メタ＝JetBrains Mono／英数＝Inter。
- 色・フォント・余白・角丸は**直書きせず** DESIGN.md トークン（`var(--color-*)` 等）参照。

### 2. 制約（プロジェクト既存ルール）

- **図はすべて SVG**（関係図・タイムライン・グラフ。ASCII/罫線アート・`<pre>` 図示は禁止）。トークン色を fill/stroke に使う。
- **レスポンシブ必須**。モバイルは device emulation の実幅で検証（window resize で済ませない）。
- 仕様 HTML を作る場合は**外部 CDN 依存禁止・全インライン**（オフラインで開ける単一 HTML）。
- 数値・出典は捏造しない前提のデータなので、**「未確認」表記をデザイン上も成立させる**（淡色セル・注記バッジ等）。

### 3. ★最重要: 日次 digest との並立を整理する導線設計

News-Grasp は既に**日次の収集ニュース digest** ページを持ち、そこに**この TODAY'S THEME（深掘り）**が daily で並立します。同じアクセス空間に「速報の一覧」と「1 テーマの読み物」が混在するとユーザーが混乱するため、両者の**情報の階層・遷移・アーカイブ（過去テーマ一覧）までの導線**を設計に含めてください。トップ LP での見せ方（digest と TODAY'S THEME の関係）、過去テーマの一覧/検索、テーマ単体ページの 3 階層を想定。

> 注: この導線/統合は本日発生した本番障害（未完成 DeepDive 要素が起因）の恒久対策とも重なる領域。別途まとめた `deepdive_integration_spec.md`（暫定統合案）も参照のうえ、つぎはぎでない全体設計として扱う。

### 4. 成果物として欲しいもの

1. テーマ単体ページのレイアウト（`━━ TODAY'S THEME` ヘッダ＋ 3 節＋各ブロックの描画）。
2. `relations`（関係図 SVG）と `table`（データ表）の**新規描画コンポーネントの見た目仕様**（レンダラ実装の指針になる粒度）。
3. 日次 digest と TODAY'S THEME の**並立を解消する導線/IA 案**（トップ LP・アーカイブ一覧・単体ページ）。
4. DESIGN.md トークンに沿った配色・タイポ・余白の指定。
