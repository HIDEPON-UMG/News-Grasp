設計を縛る 3 つの確定事実

制約 1 · headless ではスラッシュコマンド / スキル不可

公式 headless doc に「In -p mode, describe the task instead」と明記。claude -p "/deep-research ..." は使えない。さらに本パイプラインはプロンプトを stdin で渡すため argv コマンドの余地もない。→ deep-research の手法（多段 fan-out 検索・一次ソース取得・対向検証・引用付き合成）を自然言語の新プロンプト prompts/weekly-research-system.md に記述して再現する。

制約 2 · ラッパーがモデル / ツールをハードコード (必須ブロッカー)

run_claude_with_timeout.ps1 L92 が '--print --dangerously-skip-permissions --tools default --model sonnet' を固定文字列で持つ。週次の Opus 化＋検索ツール許可にはこの 1 行の引数化（後方互換）が前提。日次は引数なしで既定 sonnet のまま不変にする。

制約 3 · メール廃止により図表は SVG 一本化

当初の「フル統合（メール含む）」から公開 Web フォーカスに転換。メールが外れたことで、図表のメール用 PNG ラスタライズ（resvg 依存）が不要になり、公開 Web では純粋なインライン SVG で描ける。render_chart.py の出力は SVG 一本。

利用制限・課金（最重要の前提）

⚠ 2026-06-15 の課金変更 — 「サブスク内・追加料金なし」は 6/15 まで

2026-06-15 から claude -p（headless）は Claude サブスク枠から外れ、別建ての Agent SDK 月次クレジット（Max 5x = $100/月・API 従量レート・繰越なし）を消費する。News-Grasp は日次＋週次の両方が headless なので、両方がこの $100 を食う。クレジット枯渇後は usage credits 有効なら $ 課金、無効なら停止。→ 6/15 以降は (1) Agent SDK クレジットを claim (2) 消費を監視 (3) usage credits の有効/無効を判断、が必要。STEP0 の total_cost_usd 実測は 6/15 以降の実クレジット消費の見積もりになる。

5 時間制限（Max 5x・6/15 まで）への回答

Max 5x は約 5 時間ローリング枠（軽量モデルで ~225 msg/5h・最近倍増）＋ 週次上限（Max は最大 ~40 Opus 時間 / ~480 Sonnet 時間）。深夜の単発 Opus 実行は、直前に他の利用が無ければ枠がリフレッシュ済みのため 5 時間制限に当たりにくい。週次 Opus 上限 40h に対し 1 回数十分は極小で、既存の日次 headless も枠内で回っている。リスクは fan-out が極端に重く 1 回で枠を食い切る場合のみ → --max-turns（既定 100・最大 150）と単一テーマで抑える。万一枠に当たれば実行は途中で rate-limit され、部分生成 commit 済みなら公開・未生成なら休載（後述ガードレール）。

スコープ外 out

  • メール配信（今回の転換で廃止）
  • 読者リクエスト型（都度実行）— 今回は週次自動選定型のみ
  • 購読者向け配信の A/B テストや有料化設計
  • Deep Research 結果のファクトチェック自動化（対向検証はプロンプト内で行うが外部 fact-check API 連携はしない）
  • 既存 RSS 収集（日次 routine）部分の改変

param(
