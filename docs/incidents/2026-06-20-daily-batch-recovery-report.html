Fault boundary · 停止した工程

停止点は digest-articles-reconcile の bounded repair。repair が HTML レポート生成を試みたが、長大な inline command で ファイル名または拡張子が長すぎます が発生し、900 秒 timeout 後に 既存公開状態を維持して停止した。これは破損 publish を防ぐ安全側停止である。

02

問題の詳細と、なぜ起きたか

直接原因
bounded repair の成果物生成コマンドが長大化し、Windows の process 起動で Os code 206 を踏んだ。runner は gate が未通過のため publish へ進まず停止した。
なぜ起きたか
自動 repair が incident HTML まで inline 生成しようとし、Windows コマンドライン長という環境境界を越えた。__本文生成とコマンド起動境界__を分けていなかったことが、二次的な失敗になった。
停止/品質障害になった理由
カテゴリ digest は生成済みだったが、Summary、DeepDive、TTS、日付 docs、search audit、thumb が未完了だった。公開前 gate はこの不足を検出し、06/20 の中途半端な公開を防いだ。
補足/非原因
Scheduled Task は 06:00 に起動済みで、process も 07:31 に終了していた。認証切れ、Pages 障害、remote push 失敗はこの時点の直接原因ではない。
復旧時に見つかった問題
4件カテゴリの shortfall audit 欠落、4件の空 thumbnail、カード本文の強調 marker 不足、TTS latest_audio の前日残りが見つかった。さらに復旧後のユーザー確認で、YouTube Podcast 用 mp4 生成と upload が未実行だったことが判明した。これは __Web 公開と podcast 配信を別々の完了条件として扱えなかった__ 二次障害である。
2次
二次的に見つかった問題

自動 repair が止まった後、ローカルにはカテゴリ digest だけが残り、公開に必要な下流成果物が不足していた。__再収集ではなく不足 artifact の補完__で済む状態だったため、full rerun は行わず、当日 inventory に基づく targeted recovery に限定した。

04

直近改修・過去障害との関係

直近改修
TTS 必須化、DeepDive 必須 gate、publish inventory 強化により、06/20 は以前より多い成果物を揃える必要があった。これは公開品質を守るためには正しいが、途中停止時の不足一覧が増えた。
過去障害との関係
過去の News-Grasp 障害でも、repo 側だけ見て live runner や publish sentinel を見ないと誤判定した。今回も state JSON、当日 log、公開 sentinel を組み合わせて停止工程を切り分けた。
今回の位置付け
コンテンツ全消失ではなく、下流成果物未完了のまま repair が落ちた incident。Recovery はカテゴリ再収集ではなく、生成済み inventory を使うのが正しい。
非原因
GitHub Pages 側の停止、remote HEAD の先行更新、AivisSpeech 合成失敗は、初期停止時点の原因ではない。これらは復旧フェーズの検証対象として後段に置いた。
05

恒久対応方針の網羅性と完璧性の担保

完璧性の定義

ここでいう完璧性は、06/20 と同じ失敗 class が再発したときに、未完成公開へ進まず、必要 artifact と観測点が一意に分かることである。__自動 repair 自体の成功__ではなく、repair が失敗したときにも安全に止まり、復旧入口が明確であることを完了条件とする。

Layer 1
inline 巨大生成をやめる

incident HTML や長文 artifact はファイル経由で生成し、PowerShell command line に長大本文を載せない。

Layer 2
recovery inventory を先に出す

カテゴリ digest、Summary、DeepDive、TTS、docs、search audit、thumb の有無を1表で出してから直す。

Layer 3
shortfall audit の所有を決める

4件カテゴリは search audit を reporter 出力に必須化し、後段で偽装生成しなくてよい構造にする。

Layer 4
thumb fallback を構造化する

OGP がない媒体は外部ロゴ/媒体画像の決定ルールを持ち、空 thumb を発生させない。

Layer 5
quality gate を単一入口に寄せる

validate_daily_quality --require-deepdive を publish 直前の最終不変条件として扱う。

Layer 6
publish sentinel で完了判定する

push exit 0 では終わらず、公開 publish-status.json、audio URL、YouTube Podcast watch URL、playlist まで見る。
