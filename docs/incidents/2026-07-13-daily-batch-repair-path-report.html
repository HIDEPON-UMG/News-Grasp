02

問題の詳細と、なぜ起きたか

直接原因
daily-quality validator が先頭に WARNING を出し、その後ろに structured JSON を出した。repair matrix 側は JSON 全体ではなく、正規表現により途中の "message" 断片を artifact path として誤抽出したため、registry へ不正な CLI 引数が渡った。News-Grasp repair path は停止原因を安全側に倒したが、同一 gate の復旧には parser contract が必要だった。
なぜ起きたか
validator と repair router の境界で「標準出力は純 JSON」という暗黙契約が残っていた。一方で運用上は warning prefix を許容していたため、producer と consumer の source of truth がずれた。修正は文字列検索ではなく、最初の { から json.JSONDecoder().raw_decode で structured payload を読む形に寄せた。
停止/品質障害になった理由
当日の economy search audit は raw_results=29 に対し候補が4件で、reporter は quality_shortfall_reason を明示していた。仕様上 1-5 件の選定と理由付き shortfall は許容されるが、daily-quality validator は常に 5 件未満を失敗として扱っていた。これは __品質低下を隠すための緩和ではなく__、根拠付き shortfall を gate contract として表現するための修正である。
非原因と補足
OAuth doctor は Green であり、YouTube 認証や quota が停止原因ではなかった。podcast cover は <user-home>\Downloads\ChatGPT Image 2026年6月18日 20_27_46.png という旧端末 local path を参照しており、配信 stage で別途露出した。これは既存画像が repo から削除されたのではなく、過去から repo 管理外の端末ローカルファイルに依存していた問題だった。
2次
二次的に見つかった問題

復旧を進める過程で category hero の短い孤立行、model-eval artifact の任意性、podcast cover の portable asset 化、ffmpeg の偶数寸法保証が検出された。いずれも公開前 gate で止まるか出力品質を落とす境界であり、今回の incident に含めて最小修正と契約テストを追加した。

04

直近改修・過去障害との関係

過去障害との共通点
2026-07-11 / 2026-07-12 と同じく、runner が複数 gate の問題を段階的に露出した。共通する根は repair decision routing と artifact boundary であり、単一の Red を直して完了扱いにすると二次 Red を見落とす構造だった。
今回固有の差分
今回は editor 系ではなく、validator stdout、品質 shortfall、public video asset の portable boundary が主題だった。特に cover は git history 上 repo-managed asset ではなく、旧端末 local path を設定値として参照していた点が固有だった。
修正の境界
fallback publish は使っていない。NoPublish やローカル生成のみも完了として扱っていない。復旧は runner の通常 publish path に戻し、distribution manifest と public verification で閉じた。
再発時の観測点
次回同種障害では、runner state だけでなく validator stdout の structured payload、repair registry への引数、same-gate rerun、有効な publish anchor、podcast cover の repo asset existence を同時に見る。
05

恒久対応方針の網羅性と完璧性の担保

完璧性の定義: 同じ issue date の runner / repair / state / report が、local success だけでなく publish complete、distribution manifest、public surface、video generation、historical failure scenario までつながっていること。token-efficiency や report preflight はこの目的に従属する手段であり、停止理由にはしない。
LAYER 1
parser contract

warning prefix があっても structured JSON を正規 parser で読む。regex で message 断片を artifact path として拾わない。

LAYER 2
quality invariant

候補数 shortfall は理由と raw result 条件がある時だけ許容し、無根拠の欠落は引き続き Red とする。

LAYER 3
portable artifact

podcast cover は repo-managed default にし、env override は残す。旧端末 local path は production default にしない。

LAYER 4
render quality

category hero の短い孤立行を generator 側で再配分し、公開ページの見出し品質を gate に固定する。

LAYER 5
optional artifact

model-eval benchmark は専用 artifact が無い環境では skip とし、日次公開を不要な test fixture 欠落で止めない。

LAYER 6
historical matrix

今回の複合境界を historical failure scenario に登録し、runner / repair / state / report の横並び調査を継続させる。
