問題の詳細と、なぜ起きたか

直接原因
当日 Summary の小見出しが ### §01 [[FX]]、### §02 [[AI]] のような内部キー表記になっていた。validator は各セクションの focus label として 為替、AI、IT-Consulting、モビリティ、製造、経済、ゲーム を求めるため、summary_category_focus_invalid が7件出て daily-quality で停止した。これは表示品質だけでなく、Summary が public surface の読み出し単位になるための契約違反だった。
なぜ起きたか
editor がカテゴリ内部キーと公開向けカテゴリ名を同一視した。内部識別子としての FX / IT / Game は pipeline 内では便利だが、public Summary のセクション名としては product contract と一致しない。内部データキーと公開面ラベルの source of truth が分離されていなかったことが根であり、今回は当日 artifact を最小修正して completion gate に戻した。
二次停止点
復旧後の pytest-static は、日次公開用ではない未追跡 benchmark test を repo ルートから拾い、さらに 2026-07-13 の公開レポートが allowlist にないことで停止した。前者は runner の test discovery 境界の問題、後者は「ユーザーが明示した public incident report」と通常時の非公開契約を区別する policy 更新漏れである。retry budget で拒否という表示は、ここでは原因説明として不適切だった。
公開停止点
runner の post-deepdive 再開は docs commit、distribution manifest commit まで到達したが、git push origin main が GitHub prompt script で失敗した。gh auth setup-git 後に push は成功したが、runner の順序では push 後に Podcast finalize / verify / notification / publish-complete が続くため、手動で同じ順序を実行しなければ completion gate は podcast_pending のままだった。
影響範囲
公開前停止のため、通常経路のままでは 2026-07-14 の Web、TTS、Podcast、notification、distribution manifest、public surface が完了扱いにならなかった。復旧後は digest 7カテゴリ、Summary、DeepDive Markdown、DeepDive HTML、日付 docs、docs/publish-status.json、audio URL、daily/deepdive Podcast、notification state、live runner readiness を確認した。

二次的に見つかった問題

未追跡 benchmark ファイルが repo ルートに残り、日次公開の pytest discovery に混入した。これは content failure ではなく harness hygiene failure であり、「同じ修復を再試行すれば直る」種別ではない。retry budget はループ停止のための内部安全装置であって、ユーザー向け原因分類に使ってはならない。

05

恒久対応方針の網羅性と完璧性の担保

完璧性の定義: 日次バッチのハーネスは「同じ処理を何度も回さない」ためではなく、「公開面の正本に到達するまで、原因を typed に分類し、既存 repair path で復旧し、外部境界だけを Yellow / blocked として残す」ためにある。retry budget は内部の無限再試行防止であり、原因分類や完了報告の主語にしてはならない。
LAYER 1
Typed gate reason

pytest-static は local_contract_failure として扱う。retry budget を user-facing reason にしない。

LAYER 2
Test discovery hygiene

日次公開の static gate は tracked tests を正本とし、repo ルートの実験ファイル混入を failure class として明示する。

LAYER 3
Report approval boundary

通常時は public incident report を拒否し、ユーザー明示の automation report だけ allowlist に載せる。

LAYER 4
Sequential verifiers

live-runner readiness canary を含む verifier は並列実行しない。state/log file の競合を検証ノイズにしない。

LAYER 5
Public proof first

report preflight より public recovery を優先する。visible artifact が欠けたまま report を整えて完了扱いにしない。

LAYER 6
Historical scenario

Summary label drift、pytest contamination、push prompt、podcast pending を同じ incident の横並び調査として残す。
