Fault boundary · 停止した工程

停止境界は pytest-static。この gate は public UI の生成契約と incident report 追跡契約を同じ publish 前に見るため、局所 UI 破綻と運用 policy 漏れを同時に検出した。normal publish は止まり、fallback publish は行われなかった。

02

問題の詳細と、なぜ起きたか

直接原因
当日 IT 記事の IPA、仙台で東北サイバーセキュリティシンポジウムを11月開催 が、_category_lead_title_lines で 東北サイバーセキュリティシンポジウムを という幅 19.0 の行を作った。上限は 18.0 であり、公開前に UI 破綻として止める契約は正しく働いた。
なぜ起きたか
外販構想 や ダウンロード専売 のような既知長語は event marker で分割していたが、シンポジウム を長語境界として持っていなかった。つまり __長い一般名詞を含む行政・IT イベント名__ の fixture が不足していた。
二つ目の停止理由
前日 2026-07-17 の incident report は automation の明示指示に基づいて公開されていたが、tests/test_incident_report_tracking_policy.py の EXPLICITLY_APPROVED_REPORTS に追加されていなかった。そのため、翌日の pytest-static が 昨日の正当な公開レポートを policy 違反として検出した。
公開停止になった理由
pytest-static は publish 前の統合 gateである。docs 生成、distribution manifest、YouTube Podcast、public verifier へ進む前に rc=1 となったため、runner は normal publish を止め、壊れた HTML や policy 矛盾を push しなかった。
確認した非原因
外部 OAuth、YouTube quota、GitHub Pages outage、fallback publish、DeepDive 生成失敗ではない。DeepDive Markdown と audio-script は停止前に存在し、RecoverOnly では summary-reflection、daily-quality、generation-quality、URL liveness、record-schema、digest/articles reconcile がすべて attempt 1 で通過した。
2次
二次的に見つかった問題

runner state の original scheduled attempt は LastTaskResult=1 として残る。これは RecoverOnly 後の publish_complete と矛盾しないが、最終判定では Task Scheduler の初回失敗と runner state の復旧完了を分けて読む必要がある。

04

直近改修・過去障害との関係

2026-07-17 との関係
前日の OpenAI quoted-topic 修正は短い ASCII 主語の孤立を防いだ。本件は別パターンで、長い日本語イベント名の中間語 シンポジウム を分割境界として扱う必要があった。
report policy との関係
通常は新規 docs/incidents/*-report.html を追跡しない。しかし automation が明示的に docs/incidents への作成を要求した run は allowlist に登録して、次回 static gate で自分自身を落とさない必要がある。
過去障害との差
URL liveness、TTS 字数、Podcast、GitHub Pages timeout ではない。今回の failure domain は public UI contract と incident tracking policy の二重 static gate である。
履歴反映
本 incident は tools.historical_failure_scenarios に追加し、runner / repair / state / report の横並び調査対象として固定する。
05

恒久対応方針の網羅性と完璧性の担保

完璧性は「今日だけ通す」ではなく、同じ種類の長語 title と承認済み incident report が次回 runner を落とさないことで確認する。契約 test、historical failure matrix、RecoverOnly 実行、public verifier を同じ incident 単位で接続した。

LAYER 1
構造

長語 marker を hero title splitter に持たせ、不自然な幅超過を生成段で表現しにくくする。

LAYER 2
契約

IPA タイトル fixture と report tracking policy fixture を pytest-static に残す。

LAYER 3
運用

異常終了時は news-grasp-repair-method と RecoverOnly を使い、fallback publish を成功扱いしない。
