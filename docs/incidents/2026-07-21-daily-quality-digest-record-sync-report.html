Fault boundary · 停止した工程

停止境界は daily-quality。この gate は digest の日本語見出し、サムネ、公開前 artifact を見るため、record 正本と digest 表示の driftを検出した。normal publish は止まり、fallback publish は行われなかった。

02

問題の詳細と、なぜ起きたか

直接原因
digest/Game/2026-07-21-Game.md では record に短い title_ja があるのに、digest 見出しへ反映されず英文タイトルが残った。さらに Economy と IT の一部カードでは record/digest の thumb が空になり、公開前に fallback サムネ化を止める契約は正しく働いた。
なぜ起きたか
reporter/editor 後の record 正本には 短い title_ja と一部 thumb URL が存在していたが、既存 repair は missing thumb を quarantine/refill に倒していた。つまり __record から digest へ戻す同期境界__ の deterministic repair が不足していた。
二つ目の停止理由
復旧中に Game トップが 【怪獣8号ゲーム】スーテッド... という SEO 長文へ入れ替わり、pytest-static の category hero line quality でも停止した。これは同じく record の短い title_ja を digest 見出しへ同期すれば解ける class で、digest-record-sync-patch の対象に統合した。
公開停止になった理由
daily-quality は publish 前の content gateである。DeepDive、docs、TTS、distribution manifest、public verifier へ進む前に rc=1 となったため、runner は normal publish を止め、未翻訳 title や空 thumb を push しなかった。
確認した非原因
外部 OAuth、YouTube quota、GitHub Pages outage、fallback publish ではない。復旧 runner では summary-reflection、daily-quality、generation-quality、URL liveness、record-schema、digest/articles reconcile、ja-callout、pytest-static、deepdive-required、public-html、Podcast verification、publish-complete が通過した。

日次 publish commit 7cf32471222f2fdd5a2b6bf78cd48d6a3fd0537f は runner が push 済み。コード修正と本 incident report は別 commit として追跡し、daily content commit と repair hardening commit を分ける。

04

直近改修・過去障害との関係

2026-07-17 との関係
2026-07-19 の thumbnail parser 境界と近く、今回は Markdown alt ではなく record 正本から digest への反映漏れだった。既存 quarantine/refill に倒す前に同期できるデータを使う必要があった。
report policy との関係
今回も automation が docs/incidents への作成を明示したため、EXPLICITLY_APPROVED_REPORTS に登録して、次回 static gate で本 report 自体を落とさない。
過去障害との差
YouTube、GitHub Release、Pages timeout ではない。今回の failure domain は digest/record 同期、fallback thumb、category hero title source の content/static gate である。
履歴反映
本 incident は tools.historical_failure_scenarios に追加し、runner / repair / state / report の横並び調査対象として固定する。
05

恒久対応方針の網羅性と完璧性の担保

完璧性は「今日だけ通す」ではなく、同じ種類の record/digest drift と fallback thumb が次回 runner を落とさないことで確認する。契約 test、historical failure matrix、RecoverOnly 実行、public verifier を同じ incident 単位で接続した。

LAYER 1
構造

record の title_ja を digest 見出し正本にし、SEO 長文を category hero へ流しにくくする。

LAYER 2
契約

coverage matrix と registry fixture を追加し、未翻訳 title / null thumb を deterministic repair に残す。

LAYER 3
運用

異常終了時は news-grasp-repair-method と Resume runner を使い、fallback publish を成功扱いしない。
