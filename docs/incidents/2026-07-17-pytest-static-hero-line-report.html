02

問題の詳細と、なぜ起きたか

直接原因
`OpenAI、自動レッドチームAI「GPT-Red」発表...` の split が OpenAI を 1 行に孤立させ、quality gate が line 1 too short and isolated と判定した。
なぜ起きたか
短い日本語ブランド名を次語へ吸収する契約はあったが、短い ASCII 固有名詞 + 長い引用付き語句 のケースが契約テストに無かった。
公開停止になった理由
News-Grasp は docs 生成前に repo-wide static gate を通す。ここで止まることは、見出し崩れを公開しないための fail-closed として正しい。
確認した非原因
Scheduler 未起動、GitHub remote divergence、YouTube OAuth、URL liveness、DeepDive URL、TTS は直接原因ではない。復旧 run ではすべて Green を確認した。
二次

二次的に見つかった問題: 手動の generate_pages.py --full は過去日 2026-06-03-DeepDive.md の CBS URL 406 で停止した。今日分の復旧原因ではないが、full rebuild と日次増分 recovery の境界を混ぜない注意点として記録する。

Why the gate was correct

この停止は、公開前にユーザー可視の見出し崩れを止めるという News-Grasp の fail-closed 設計に沿っている。問題は gate の存在ではなく、generator が許容すべきタイトル型を表現できていなかった点にある。したがって対応は gate の弱体化ではなく、入力タイトルを読みやすい行へ分解する契約の追加に限定した。

復旧判断では、runner state、当日ログ、publish manifest、public surface proof を分けて確認した。06:40 時点でプロセスは残っておらず、同一 stage の異常滞留や無限ループではなく、pytest-static の明示的な rc=1 停止だったため、バッチ中断操作は不要だった。

04

直近改修・過去障害との関係

関連する直近改修
Category Hero Turn 4 の見出し折返し品質 gate。公開前に崩れを止める目的自体は正しい。
過去障害との違い
publish convergence や OAuth ではなく、repo-local generator の contract gap。外部 Yellow ではなく local Red として扱う。
類似候補
短い固有名詞を先頭に持つ企業名、AIサービス名、ゲーム機名。今回のテストは引用付き語句へ絞り、過剰な改行変更を防いだ。

過去の publish convergence 系障害では、成果物生成後の remote reflection や GitHub Pages 反映が主な観測点だった。今回は生成前の contract gap であり、publish retry や URL 監視を増やしても根本原因は消えない。そのため、repair method の優先順位どおり、validator/generator の契約を修正してから production repair path で再実行した。

また、今回の復旧では fallback publish を成功扱いにしていない。daily runner の通常 publish-complete manifest、公開 URL の同日 sentinel、DeepDive HTML、distribution manifest、Podcast verification を同じ issue date でそろえてから完了判定した。これにより、ローカル修正だけ完了して公開面が旧日付のまま残る事故を避けている。

未到達 stage は復旧 run で再実行し、手編集の HTML 差し込みで代替しなかった。次回同型タイトルが来ても、同じ contract test と runner gate が検知・通過条件を持つ。
