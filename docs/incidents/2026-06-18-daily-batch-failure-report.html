2. 問題の詳細となぜその問題がおきたか

ROOT CAUSE
直接原因
寄与要因
防御の挙動
直接原因 runner の pytest 実行が一時ディレクトリを明示しておらず、pytest が %LOCALAPPDATA%\Temp\pytest-of-hideki を走査して PermissionError [WinError 5] で失敗した。
なぜ起きたか Scheduled Task / 非対話 runner の実行環境では user temp の権限・残骸・所有状態が安定しない。 それにもかかわらず、pytest の base temp を repo-local に固定していなかった。
停止が公開停止になった理由 News-Grasp は公開前 gate をすべて通過してから digest/data commit、docs 生成、push に進む設計である。 pytest-static の非0終了により、runner は content_repair_failed として公開を止めた。
repair が救えなかった理由 bounded repair は runner や一時 pytest artifact など artifact scope 外の変更を検知した。 これは安全側の停止であり、未検証の修復差分を公開しないための guard が働いた状態である。

二次的に見つかった問題

復旧中に URL liveness gate が WSJ 3 件を session 未確認 かつ 401 として拒否した。 これらは公開対象から外し、Summary と audio-script からも該当論点を除いて整合させた。

完璧性の定義

ここでいう完璧性は「未知の全障害が絶対に起きない」ではなく、 今回と同じ class の障害が再導入された場合に、公開前または契約テストで検出できることと定義する。 今回の class は user temp 依存、repo/live drift、未検証修復差分の混入、途中再開不備である。

Layer 1

失敗を表現しにくくする

pytest は repo-local temp に固定し、user temp の権限状態に依存しない。

Layer 2

境界で集約する

runner の pytest gate に固定し、個別手順や運用注意ではなく実行経路で担保する。

Layer 3

契約テストで固定する

runner から basetemp 固定が消えたら契約テストが fail する。

Layer 4

live 同期を完了条件化する

repo runner 修正後は install と SHA256 一致を必ず done criteria に含める。

Layer 5

公開 inventory を列挙する

7カテゴリ digest、Summary、DeepDive、docs、publish-status、URL sentinel を確認する。

Layer 6

scope 外修復を止める

bounded repair が範囲外を触った場合は公開しない。今回もこの防御で未検証 push を防いだ。
