Fault boundary

Fault boundary は runner 本体処理ではなく、その前の production predicate である。E2E output namespace と production predicate が同じ当日 path を見ていたため、build/reporter-artifacts/2026-06-28 が本番日次の既存成果物として扱われた。

02

問題の詳細と、なぜ起きたか

直接原因
pre-DeepDive E2E / NoPublish の成果物が build/reporter-artifacts/2026-06-28 に残り、production runner の Test-DailyArtifactsExist が same-date artifact と判定した。
なぜ起きたか
作業側の成果物整理は人間の見た目や一部ファイル確認に寄っており、runner と同じ predicate / glob / stateで空であることを確認していなかった。
本番停止化した理由
Production Predicate Inventory が未作成だったため、E2E artifact cleanup の完了条件が runner の実判定と同期していなかった。結果として 本番前提を壊す artifact contamination を見逃した。
非原因
この衝突はフル runner 内部の wrapper / repair / URL liveness bug とは別である。本番 runner 障害とは別扱いにし、フル runner の根本原因として扱わない。
証跡
計画上の確認対象は scripts/ops/news-grasp-runner.ps1 の Test-DailyArtifactsExist、build/reporter-artifacts/2026-06-28、既存 docs/incidents/2026-06-28-daily-batch-recovery-report.html、pre-DeepDive E2E report である。
2次
二次的に見つかった問題

E2E output namespace が production artifact namespace と交差していた。さらに、cleanup 完了を同一 predicate で証明しないまま本番バッチ準備完了と扱える報告プロセスも問題だった。public URL proof は未承認なので、この report では Local Green と Publication Pending Approval を分ける。

恒久対応方針の網羅性と完璧性の担保

OK

恒久対応の基準は、E2E を回した後に成果物を目視整理することではない。production predicate と同じ評価軸で cleanup を確認し、E2E output namespace と production namespace を分離し、historical failure matrix に report artifact を登録することで再発を防ぐ。

LAYER 1
Production Predicate Inventory

runner が見る glob、state file、artifact root を report と test に固定する。

LAYER 2
E2E output namespace

検証成果物を production path へ残さない。残す場合は本番 guard と同等の cleanup proof を要求する。

LAYER 3
same-predicate verification

cleanup の PASS は Test-DailyArtifactsExist と同じ判定で証明する。

LAYER 4
report contract

E2E衝突を full runner report に混ぜず、別HTMLとhistorical matrixで検査する。

LAYER 5
Local Green

validator、render、pytest を local で通す。ただし public URL proof は未承認のため言わない。

LAYER 6
Publication Pending Approval

commit / push / Pages / public proof は別途承認後に移す。
