Fault boundary · 今日の障害境界

一次停止は tools/refill_category_after_quarantine.py 周辺の refill 判定境界で発生した。復旧後の二次障害は tools/generate_pages.py の Summary markdown 境界で発生し、## KEY TAKEAWAYS が ESSAY 最終節の本文に吸い込まれた。どちらも 後続ブロックをどこで切るか の契約が不足した境界障害である。

02

問題の詳細と、なぜ起きたか

直接原因 1
日次 runner は URL liveness 後の it refill で blocked_refill_unresolved となり、publish へ進めなかった。audit で落ちた URL が reserve 候補に残り、shortfall を安全に許容できない判定になっていた。
直接原因 2
復旧後の Summary は ## KEY TAKEAWAYS を使っていたが、SSG parser は ### KEY TAKEAWAYS だけを境界としていた。そのため ESSAY §09「明日へ」が後続の color: や Related Issues を本文として取り込んだ。
なぜ起きたか
両方とも、正常系の量が揃う前提に依存していた。refill 側は 1件以上の shortfall を許容する設計 が弱く、Summary 側は H2/H3 の見出し揺れ を契約として持っていなかった。
品質障害化した理由
一次障害は公開が止まったため即検知された。一方で二次障害は公開後の本文見た目で分かる障害で、HTML validator では構文上正常だった。つまり 構文ではなく意味境界のテスト が必要だった。
非原因
DeepDive 本文、DeepDive podcast、daily podcast、GitHub Pages の deploy 自体は復旧後に確認済み。Summary の混入は CSS ファイル破損ではなく、HTML へ CSS 風の color: 文字列が本文として出ていた parser 境界の問題だった。
2次
二次的に見つかった問題

公開後に ESSAY「明日へ」へ ## KEY TAKEAWAYS - n: 1 / color: ... が混入していた。これは CSS そのものではなく、Structured markdown の属性断片が本文としてレンダリングされたもの。修正後は公開URLから「明日へ」本文を抽出し、KEY TAKEAWAYS、color:、Related Issues、[!link] がないことを確認した。

03

問題の暫定対応内容

Morning

日次バッチが完走していないことを検知。停止理由を blocked_refill_unresolved と特定し、対象を refill/audit の URL 除外境界に絞った。

Recovery 1

tools/refill_category_after_quarantine.py を修正。1件以上の shortfall を許容し、正式カード同期と audit dropped URL の reserve 除外を入れた。

Recovery 2

daily quality、publish verify、DeepDive podcast、daily podcast を確認。commit e8a8668、9e6e36a、9349f15 で復旧内容を push。

Post-publish

公開後に Summary ESSAY「明日へ」の構造化断片混入を検知。H2 ## KEY TAKEAWAYS を再現テストで失敗固定した。

Final

tools/generate_pages.py を H2/H3 境界対応に修正し、dfb6b4b で公開。公開URL 200 と本文 leaks=[] を確認した。

Mitigation 1

refill復旧

shortfall と dropped URL を同時に扱い、候補不足時でも公開可能な最小集合に収束させた。

Mitigation 2

公開sentinel

publish-status.json を published_ok とし、remote HEAD と公開URLを確認した。

Mitigation 3

Podcast確認

Daily podcast 5kY29HRVaF0 と DeepDive podcast flDwiI5rpS8 を確認した。

Mitigation 4

Summary境界修正

ESSAY 本文だけを抽出して混入なしを検証。SW_VERSION も bump した。

04

直近改修・過去障害との関係

直近改修
7:30 runner wait の削除、日次更新時刻変更、DeepDive dialogue / podcast 統合が直近に入っていた。ただし今回の停止直接原因はそれらではなく refill の URL 除外契約だった。
過去障害との関係
6/18 以前の公開停止系と同じく、生成物自体よりも公開前 gate / 境界条件が停止点になった。今回の追加差分は、公開後の Summary 表示品質も同じ日付の障害に含めた点である。
同型性
refill も Summary parser も、入力の揺れを想定した境界が不足していた。境界に入る前に落とす のではなく、境界自体を契約テストにしたことが今回の再発防止策である。
05

恒久対応方針の網羅性と完璧性の担保

今回の恒久対応は、個別の smoke 追加ではなく、入力境界を表現できる契約テスト と parser / refill 側の不正状態排除で担保する。refill は dropped URL を候補から外す。Summary は H2/H3 の KEY TAKEAWAYS を ESSAY 境界として認識する。これにより、同じ見出し揺れや URL 除外状態が来ても、壊れた公開物に進みにくい。

Layer 1

refill契約

shortfall と dropped URL の扱いをコードとテストに固定。

Layer 2

Summary境界

H2/H3 の KEY TAKEAWAYS を本文境界にし、§09 への混入を止める。

Layer 3

公開検証

remote HEAD、Pages deploy、publish verify、公開HTML本文抽出を確認。
