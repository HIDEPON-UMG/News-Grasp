02

問題の詳細と、なぜ起きたか

直接原因
Summary の §03、§05、§06、§07、§08 が daily-quality の強調契約を満たさず、下線強調 __...__ の欠落として停止した。これは記事本文全体の破損ではなく、公開前の editorial reflection contract で検出された局所品質エラーである。
なぜ起きたか
完全自走化の repair 原則により、既存 artifact がある場合の LLM 全再作成は pre-repair policy で止まった。これは「一から作り直さない」方向としては正しいが、Summary 強調不足を determinisitic repair で直す経路が足りなかった。
停止/品質障害になった理由
resume 名称と実行順序が一致していなかったため、DeepDive、docs、TTS に進む前に daily-quality を再判定した。結果として、復旧指示後の runner も fallback を再公開し、公開面は 06-25 へ進まなかった。
非原因
7カテゴリ digest 自体は存在しており、記事収集全体が空だったわけではない。Podcast/音声も復旧時点では 06-25 用に生成・公開できたため、外部 TTS または GitHub Release の永続障害ではなかった。問題は 欠落 artifact を作る順番と gate のかけ方にあった。
検知できた証跡
docs/publish-status.json は published_fallback_with_notice のまま残り、validate_daily_quality は docs / DeepDive / TTS 欠落と Summary 強調不足を示した。復旧後は PASS: daily quality OK (2026-06-25) と public URL 200 sentinel を確認した。

04

直近改修・過去障害との関係

完全自走化との関係
既存 artifact があるときに LLM worker へ丸ごと再生成させない policy は、上流で無駄を止める方向として正しい。一方で、Summary 強調不足のような局所欠陥を deterministic repair で補う実装が足りず、policy が「再作成防止」だけで終わった。
曜日別カテゴリ障害との関係
今回の 06-25 は木曜日で Game / Manufacturing / Economy すべて対象のため、曜日別カテゴリ誤判定そのものが直接原因ではない。ただし spec に正本が欠けていたため、全体 pytest が失敗し、復旧 commit 前に Category Schedule Source of Truth を追加した。
過去 fallback 障害との関係
fallback は壊れた公開を防ぐためには必要だが、通常公開が復旧した後は published_ok へ戻す必要がある。今回も docs/publish-status.json が fallback のまま残ったことが、公開未更新の強い証跡になった。
goal 未達との関係
goal が完走扱いになった場合でも、公開 URL、Podcast/音声、publish-status、DeepDive、カテゴリページの実公開 sentinel が揃っていなければ未達である。今回の復旧では、local generation ではなく public URL 200 までを完了条件に戻した。
05

恒久対応方針の網羅性と完璧性の担保

完璧性は「止まらない」ではなく、上流で無駄な再作成を禁止し、局所欠陥は局所 repair し、それでも公開面が揃わない場合だけ停止することと定義する。今回の恒久対策は runner の resume 順序、Summary deterministic repair、publish verification、spec contract の 4 層で閉じる。

LAYER 1

上流防止

Summary 生成時点で required emphasis を満たす。非対象カテゴリや不要な全再生成へ流す前に、正本仕様で対象を絞る。

LAYER 2

局所 repair

既存 artifact がある場合は、LLM 丸ごと再作成ではなく該当節・該当図表・該当音声原稿だけを修復する。

LAYER 3

公開面 gate

local PASS では終わらず、publish-status、date page、summary audio、DeepDive audio、カテゴリ URL を public URL で確認する。

LAYER 4

resume contract

post-daily-quality は daily-quality を先に再実行せず、DeepDive/docs/TTS を作った後に publish gate へ進む契約へ直す。

LAYER 5

SLO 境界

40分で半分未満なら異常として停止・原因分析へ切替える。2時間まで待つ運用に戻さない。

LAYER 6

証跡主義

goal 完了はローカル生成ではなく、remote HEAD、Pages success、公開 URL sentinel、音声/Podcast 状態までを根拠にする。
