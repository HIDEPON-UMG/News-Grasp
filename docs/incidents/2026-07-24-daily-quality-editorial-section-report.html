Fault boundary · 停止した工程

Fault boundary は daily-quality の thumb_invalid_or_missing 判定である。ログでは digest\FX\2026-07-24-FX.md: card #05 §01 総論 — 円安の材料が重なる が thumb 空と扱われたが、これは元記事 URL を持たないカテゴリ考察セクションであり、公開カードではない。したがって、停止は壊れた記事カードの検出ではなく、validator の対象選別が広すぎたことによる local defectである。

02

問題の詳細と、なぜ起きたか

直接原因
tools.validate_daily_quality.validate_digest_article_thumbnail_coverage が parse_articles() の返す要素をすべて記事カードとして扱い、元記事 URL を持たない editorial section まで thumb 検査した。今回の FX digest では下部の ### §01 総論 — 円安の材料が重なる が card #05 として扱われた。
なぜ起きたか
parse_articles() は生成ページ用の汎用パーサであり、記事カードとカテゴリ考察を同じ ### 見出しから拾える。validator 側が source_url / url の有無で公開カードだけに絞る境界を持っていなかった。
停止が正しかった点
News-Grasp は通常公開で fallback thumb を許容しないため、記事カードの thumb 欠落は publish 前に止めるべきである。今回も runner は docs 生成と push に進まず停止しており、公開前 gate の fail-closed 動作自体は正しい。
修正方針
品質条件を弱めず、対象だけを正規化した。source_url または url を持つ実記事カードは従来どおり thumb 検査し、元記事 URL を持たない editorial section は thumb gate の対象外とした。契約テストで 実記事は落とす / §NN 考察は落とさないを同時に固定した。
2次
二次的に見つかった問題

復旧 runner の URL liveness gate は一度 rc=1 になり、既存の quarantine/refill path で修復された。これは同じ日付の公開面には残っていないが、URL liveness と daily-quality が同一 incident で連続したため、runner lane と repair lane の両方で証跡を残した。

05

恒久対応方針の網羅性と完璧性の担保

完璧性の定義は、記事カードの fallback thumb を今後も落としつつ、カテゴリ考察のような公開カードではないセクションを誤検出しないことである。実装は source_url / url をカード境界にするため、今回のような `### §NN` heading の追加に対して低コストで安定する。

LAYER 1

Validator boundary

thumb gate は source URL を持つ公開カードだけを対象にする。parser の広い抽出結果をそのまま品質 failure にしない。

LAYER 2

Contract tests

空 thumb の記事カードは Red のまま、editorial section は Green にする。防御を弱めず、誤検出だけを閉じる。

LAYER 3

Same-gate recovery

修正後は同じ daily-quality / deepdive-required / publish-complete gate で再検証する。URL 200 単独の成功扱いはしない。

残る注意点は、今回の fix commit 77e12adc と当日公開 commits がすでに remote へ反映済みである一方、レポート自体はこの後に別 commit として追加される点である。公開レポートの validator / render check / public URL sentinel は、レポート commit 後に別途同じ証跡として残す。
