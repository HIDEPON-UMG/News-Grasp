Fault boundary · 停止した工程

停止点は tools.auto_repair_orchestrator classify 実行後の結果読込である。runner は FileNotFoundError: news-grasp-repair-classify-daily-quality-2026-06-27-attempt1.json を受け、公開前に停止した。このため E2E の一時生成成果物は production publish へ流れず、修正後の NoPublish 2回目でも commit / push / upload / send_push を実行していない。

02

問題の詳細と、なぜ起きたか

直接原因
Invoke-LoggedCapture の wrapper parameter $CapturePath と、呼び出し元が scriptblock 内で参照した $capturePath が PowerShell の case-insensitive な名前解決で衝突した。classify は gate 出力ではなく classify 出力を入力として読みに行き、結果 JSON が存在しないため停止した。
なぜ起きたか
PowerShell の & $Block は scriptblock の未束縛変数を wrapper function 側のローカル変数へ解決し得る。通常 E2E は正常系の gate 通過を確認していたが、wrapper parameter と block 内変数の衝突 という異常系を固定していなかった。
停止が公開停止になった理由
News-Grasp は公開前 gate が Green になってから docs 生成、distribution manifest、push、send_push へ進む。classify の失敗は gate 判定不能であり、runner は 未検証の成果物を公開しない 側に倒れた。
確認した非原因
YouTube OAuth は auth doctor で ok=true、reauth_required=false。Scheduled Task は翌日 06:00 に登録済みで、live runner と repo runner の SHA256 は一致。外部認証や task 登録欠落ではなく、runner 内の scriptblock 変数衝突が直接原因だった。
2次
二次的に見つかった問題

1回目の NoPublish E2E は publish dry-run まで進んだが、distribution manifest has changes, committing に到達した。これは NoPublish なのに repository commit 副作用が残る 契約漏れであり、同日中に backup branch 作成、mixed reset、生成物 restore、runner 修正、2回目 NoPublish E2E で解消を確認した。

MITIGATION 4

NoPublish E2E の一時生成成果物は公開していない。公開 URL 200 確認は既存公開面が壊れていないことの確認であり、E2E 成果物公開ではない。

04

直近改修・過去障害との関係

直近改修との関係
auto repair classify 経路は gate 失敗時にだけ通るため、通常系 E2E では見落としやすい。修正は runner の分類補助経路に限定され、通常 publish path そのものを置き換えていない。
過去 E2E との関係
従来の E2E は正常 path と単発異常 path の確認に寄っており、PowerShell の動的スコープ衝突 と NoPublish 下の distribution manifest 副作用 を compound case として固定していなかった。
公開面との関係
production publish は 12:17 に完了している。NoPublish E2E の一時成果物は公開しておらず、公開 URL 200 は既存公開面の健全性確認として扱った。
非原因
YouTube OAuth、Scheduled Task 登録、GitHub remote HEAD、live runner sync は復旧後に Green。根本原因ではなく、復旧・翌日自走の確認対象である。
