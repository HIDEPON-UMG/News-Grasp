直接原因

04

直近改修・過去障害との関係

E2E 成果物整理
pre-DeepDive E2E / NoPublish E2E の成果物が本番日付と衝突した。今回のハーネス変更では、計画/TODO 時点で Source-of-Truth Predicate Inventory、runtime glob/state inventory、side-effect surface、same-predicate verification を要求する。
過去 repair バグ
repair matrix に行があっても handler 未実装、artifact scope 不足、state consistency 欠落があると自走復旧できない。今回 digest-articles-reconcile-patch と audio closing drift repair を契約テストつきで追加した。
fallback 重大障害
外部障害ではない内部 quality gate failure を fallback notice で成功扱いしたことが今回の最大の運用違反だった。新契約では content / artifact / local-tool は fallback publish へ進まず停止する。
DeepDive URL 事故
捏造 URL 防止 gate は必要だが、全履歴を日次 SSG の責務にすると経年 404 が当日公開を止める。本日分 publish gate と履歴監査を分離することで、品質担保と自走性を両立させた。

恒久対応方針の網羅性と完璧性の担保

OK

恒久対応の判断基準は「止まったら人が復旧」ではなく、既知の内部不整合を repair / state reconciliation / contract test / runner boundary で処理し、外部障害以外の block を成功扱いしないこと。今回の publish はこの基準で Green になった。

LAYER 1
入口衝突防止

実装 predicate と同じ glob/state で E2E 成果物を評価し、作業者目視との差分を plan_quality_guard で遮断する。

LAYER 2
success probe

Codex 子プロセスが終了しなくても、成果物 gate が Green なら wrapper が子 tree を止めて前進する。

LAYER 3
deterministic repair

articles/date URL mismatch と audio closing drift を handler 実装で復旧し、coverage matrix で handler 未実装を Red にする。

LAYER 4
内部 block 厳格化

content / artifact / local-tool failure は fallback notice へ進まず、runner state と exit code で失敗を残す。

LAYER 5
current-only publish gate

本日分 URL は厳格に検証し、履歴 URL 監査は別ジョブ・別責務へ分離して日次公開を妨げない。

LAYER 6
public proof

remote HEAD、Deploy Pages、public status、audio、podcast、manifest を同一 run intent で検証してから完走扱いにする。
