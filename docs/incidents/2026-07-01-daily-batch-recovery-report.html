02

問題の詳細と、なぜ起きたか

直接原因
live runner が repo の runner と drift しており、06:00 の Scheduled Task は runner binary drift requires backup + explicit approval + rollback plan で停止した。同期後も、当日生成物の曜日・字数・関係図配置が gate 条件を満たさず、最終的に pytest-static が Home Variant B の DeepDive カード構築失敗を検出した。
なぜ起きたか
runner drift は live install の反映状態が本番 runner に残っていたため発生した。コンテンツ側は、LLM 生成物 が日付曜日、音声台本長、DeepDive 関係図の幾何制約をすべて同時に満たすとは限らないのに、生成後 gate が publish 前に束ねて検出する構造だった。
停止/品質障害化
DeepDive の relations 自動配置で複数線がノード円を貫通し、tools.output_quality.check_relations_svg がカード構築を拒否した。この結果、公開前 gate が正しく壊れた成果物を止めた 一方、通常バッチは public push へ進めなくなった。
repair / 非原因
URL liveness、record schema、digest/articles reconcile、ja-callout、YouTube OAuth、GitHub Pages、audio release は復旧後に Green だった。__外部公開基盤の障害ではなく__、live runner 同期と当日生成物品質 gate の複合停止 と分類する。
確認済み結果
07:04 時点で runner state は publish_complete、local / remote HEAD は 7ce4c2e13fd5c5de8f6ecec675f41a3bd7a6a7d6 で一致。Deploy Pages workflow は completed/success、public PWA は 2026-07-01-category-label-wrap、Daily Podcast は MpkDZ_yVY5s、DeepDive Podcast は TD2lQ6v35cY で oEmbed 検証済み。
