最初の停止点は tools.refill_category_after_quarantine の入口である。--list-categories が返した JSON 配列が PowerShell native command 呼び出し時に 1 つの結合値として扱われ、fx ai it mobility manufacturing economy game が --category に渡った。Python argparse は先頭以外を未認識引数と見なし rc=2 で停止した。

02

問題の詳細と、なぜ起きたか

直接原因
prompts/newsroom-editor-system.md の曜日表が水曜を fx, ai, it, mobility, manufacturing, economy の 6カテゴリとして扱い、runner が収集した Game reporter records 5件を編集長 append 対象から落とした。Game は探せていなかったのではなく、reporter records から digest/articles へ渡す工程で破断していた。
なぜ今日起きたか
News-Grasp Runner は全7カテゴリを処理するが、編集長 prompt は 2026-06-12 の曜日表導入以降、Game を火木土日だけと記述していた。2026-06-24 は水曜だったため、runner と editor prompt の source-of-truth drift が顕在化した。
Podcast 未公開
復旧 commit bdb32cd095011e184a084810c1cf3d052850ce43 後、サイトと Release MP3 は 200 だったが、build/youtube-podcast/uploads.json と build/youtube-podcast-deepdive/uploads.json に 2026-06-24 が無かった。手動復旧で verify-publish-complete を最後に通さず、YouTube Podcast 2本の未公開を見落とした。
goal 自走失敗
6時間自走と 3,659,533 tokens は、fallback publish と repair retry には使われたが、通常公開完了条件を publish-status と HTML だけに寄せてしまい、Game append と Podcast finalize を同一ゴールの必須条件として固定できなかった。
安全側に働いた点
fallback は壊れた通常公開を避ける点では安全だった。しかし、ユーザーの期待値は 1時間以内の通常公開 であり、fallback を「復旧に近い状態」と扱った時点で SLO と目的を外した。
2次
二次的に見つかった問題

当日の既存レポートは URL/refill と古い Game 残留を中心に書かれており、Podcast 未公開と goal 自走の打ち取り失敗を主因級に扱えていなかった。障害レポート自身も 復旧完了条件の矮小化を再生産していたため、本版で大障害として統合した。

04

直近改修・過去障害との関係

非対話出力契約
同日に実施した CODEX_NONINTERACTIVE_SESSION=1 / CODEX_OUTPUT_CONTRACT=artifact-gate は、完了報告フォーマット強制を緩めた。一方、URL session 台帳は別の hook 成果物であり、これも非対話 runner の必須条件から外す必要があった。
URL liveness 強化
死リンクや偽日付を公開しない思想は正しい。今回の問題は URL gate そのものではなく、refill 引数境界と session 台帳依存が過剰だった点にある。
DeepDive 配信必須化
YouTube Podcast / DeepDive audio を必須配信物にしたことで品質は上がったが、対談台本が runner の生成責務になっていなかった。必須物は runner が生成または検証できなければならない。
pytest temp 問題
過去の user temp / permission 問題と同系統である。repo-local .pytest-tmp 固定の契約は既に存在し、今回も最終 run では通過した。今後は runner repair がこの種の環境差分を拡大しないことを重視する。
05

恒久対応方針の網羅性と完璧性の担保

完璧性の定義は「HTML と publish-status が見える」ではない。Game を含む当日カテゴリ、Release 音声、Daily Podcast、DeepDive Podcast、remote HEAD、Pages、PWA が同じ日付・同じ公開 commit に束ねて検証されることを完了条件にする。goal 自走はこの完了条件を固定できず、fallback と partial recovery を通常公開に近いものとして扱ったため失敗した。

LAYER 1
カテゴリ正本を manifest 化

編集長 prompt の曜日表ではなく、runner の editor-input-manifest.json を当日の実カテゴリ正本にする。

LAYER 2
Game 0件を gate 化

reporter records に Game があるのに digest/articles が 0 件なら、fallback でなく通常公開未達として止める。

LAYER 3
Podcast 必須完了判定

手動復旧でも verify-publish-complete を最後に通し、uploads.json と YouTube watch/playlist を確認する。

LAYER 4
SLO と token 上限

1時間通常公開を SLO とし、repair retry と token 消費が SLO を超えた時点で fail loud にする。

LAYER 5
goal 成功条件の再定義

fallback、partial publish、Podcast 未公開を goal 達成から除外し、通常公開のみ Green とする。

LAYER 6
障害レポート品質 gate

レポートは単一原因だけで閉じず、前工程・当該工程・後工程・runtime state・公開面・未検証を網羅する。
