Fault boundary

最初の停止点は tools.refill_category_after_quarantine の入口である。--list-categories が返した JSON 配列が PowerShell native command 呼び出し時に 1 つの結合値として扱われ、fx ai it mobility manufacturing economy game が --category に渡った。Python argparse は先頭以外を未認識引数と見なし rc=2 で停止した。

02

問題の詳細と、なぜ起きたか

直接原因
URL liveness quarantine 後の refill で、カテゴリ一覧 JSON をPowerShell 配列として安全に正規化せず、native command 引数へ渡した。結果として --category の値が単一カテゴリではなく複数カテゴリ結合値になった。
なぜ起きたか
PowerShell と Python の境界で、JSON 配列、PowerShell 配列、native command 引数配列の 3 種を同一視していた。PS 5.1 互換 runner ではここを明示的に文字列リストへ flatten する必要がある。
復旧過程で見つかった問題
07:37 の復旧では URL 本体は 204/204 OK、日付証拠も 54/54 OK だったが、session whitelist 不在だけで --require-session が fatal になった。これは人間対話 hook の成果物を非対話 runner の必須条件にした設計不整合である。
DeepDive 音声停止
07:56 には digest/DeepDive/2026-06-23-DeepDive-dialogue.md が無く、tools.tts.deepdive_dialogue が FileNotFoundError で停止した。手動補完で復旧したが、そのままでは次回も欠落時に止まる。
安全側に働いた点
runner は公開前 gate が通らない限り docs 生成と push に進まない。これは公開停止の直接要因でもあるが、壊れた記事・音声・URL を出さないためには正しい境界である。修正対象は gate を弱めることではなく、gate の前提を非対話 runner に合わせることである。
2次
二次的に見つかった問題

復旧中の pytest-static は一度 repair worker を呼んだ。ここでは過去の user temp / scope 由来問題が再浮上し得るため、repo-local .pytest-tmp 固定の契約を引き続き保持する。今回は最終復旧 run で pytest gate は attempt 1 で通過した。

04

直近改修・過去障害との関係

非対話出力契約
同日に実施した CODEX_NONINTERACTIVE_SESSION=1 / CODEX_OUTPUT_CONTRACT=artifact-gate は、完了報告フォーマット強制を緩めた。一方、URL session 台帳は別の hook 成果物であり、これも非対話 runner の必須条件から外す必要があった。
URL liveness 強化
死リンクや偽日付を公開しない思想は正しい。今回の問題は URL gate そのものではなく、refill 引数境界と session 台帳依存が過剰だった点にある。
DeepDive 配信必須化
YouTube Podcast / DeepDive audio を必須配信物にしたことで品質は上がったが、対談台本が runner の生成責務になっていなかった。必須物は runner が生成または検証できなければならない。
pytest temp 問題
過去の user temp / permission 問題と同系統である。repo-local .pytest-tmp 固定の契約は既に存在し、今回も最終 run では通過した。今後は runner repair がこの種の環境差分を拡大しないことを重視する。
05

恒久対応方針の網羅性と完璧性の担保

完璧性の定義は「今回の入力だけ通る」ではない。非対話 runner が、人間向け hook 成果物、PowerShell の暗黙配列展開、手作業台本補完に依存しないこと、かつ公開前 gate は URL・日付・音声・docs・podcast の実体を確認し続けることを完了条件にする。

LAYER 1
境界正規化

JSON 配列は PowerShell で明示 flatten し、native command へ 1 値ずつ渡す。空白入り category は拒否。

LAYER 2
非対話 gate 契約

session hook 台帳は warning と診断材料に留め、URL 物理確認・日付証拠・公開 sentinel を本線にする。

LAYER 3
必須配信物生成

DeepDive 本文から対談台本を deterministic に生成する CLI を追加し、TTS 前に runner が必ず呼ぶ。

LAYER 4
契約テスト

runner convergence、session URL、DeepDive dialogue builder、distribution gate の 7 件で固定。

LAYER 5
公開面検証

remote HEAD、publish-status、当日トップ、DeepDive URL、podcast sentinel を確認する。

LAYER 6
運用レポート

単一停止点だけでなく、復旧中に露出した契約不整合を同一レポートで俯瞰する。
